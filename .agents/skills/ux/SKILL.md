# UX review

Apply before implementation and again to the concrete result. Make and verify fixes within the
user's authorized scope. No additional approval is required by this skill.

1. Name the reader's next action. Make navigation, page status, and the primary action apparent.
2. Use a coherent visual hierarchy: readable measure, calm typography, deliberate spacing,
   consistent colors, and useful contrasts between prose, SQL, output, and explanations.
3. Make content beautiful through clarity and structure. Avoid decoration that competes with evidence.
4. Check keyboard navigation, visible focus, semantic headings, labels, contrast, and status announcements.
   Do not rely on color alone. Keep tables and plans scrollable without widening the whole page.
5. Show loading, success, empty, and error states. Offer reset and recovery. Never silently lose work.
6. Inspect a representative complete page at desktop and narrow mobile widths. Check navigation,
   SQL editing, output overflow, and sticky controls. Use real browser screenshots.
7. Test the primary journey on the built site under its GitHub Pages subpath. Treat asset failures,
   unreadable output, hidden controls, or misleading completion states as release blockers.

Record a concise review: what was inspected, issues fixed, and any material remaining limit.
